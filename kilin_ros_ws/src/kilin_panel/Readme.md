## Kilin Panel

Kilin Panel is a PyQt5-based GUI for the Kilin robot used to control power stages and send motor commands via ROS2 topics. It provides quick controls for power (digital/signal/power), per-module motor command composition, motor state feedback display, logging triggers and a helper button to start/stop a ROS2 bridge process.

---

## Quick start — run the panel

Prerequisites:
- ROS 2 (a supported distribution) installed and sourced.
- Python 3 with PyQt5 available (e.g., `python3 -m pip install PyQt5` or your system package manager).
- The `kilin_msgs` package installed (message definitions used by this panel).

Recommended (in workspace containing this package):

1. Build and install the package using colcon (from your workspace root):

```bash
colcon build --packages-select kilin_panel
source install/setup.bash
```

2. Launch the GUI with the provided launch file:

```bash
ros2 launch kilin_panel kilin_panel.launch.py
```

Alternatively, run the installed console script:

```bash
ros2 run kilin_panel kilin_panel
```

Or run directly from the package directory (for quick dev/testing):

```bash
cd <your_workspace>/src/kilin_panel
python3 src/kilin_panel.py
```

Notes:
- Ensure you have a running ROS 2 environment and that the topics `/power/state`, `/motor/state`, `/kilin/motor_cmd_raw` and `/motor/command` are available as required by your configuration.

## What each file does

This package places Python modules in `src/`. Below is a per-file summary of the Python sources and their role.

- `src/kilin_panel.py`
  - Main application module. Implements the `KilinPanel` Qt main window class which:
    - Builds the UI using `Ui_MainWindow`.
    - Initializes ROS2 (`rclpy`) and creates two ROS nodes (`PowerNode` and `MotorNode`).
    - Hosts four `ModulePanel` widgets (modules A..D) for motor command editing.
    - Handles power toggles (digital/signal/power), emergency stop, sending motor commands, and switching between UI/Manual control modes. In Manual mode the panel forwards `/kilin/motor_cmd_raw` → `/motor/command` and makes module inputs read-only so the operator can monitor commanded values.
  - Contains the `main()` entry point used by the console script (`kilin_panel = kilin_panel:main`).

- `src/mainwindow.py`
  - Generated PyQt5 UI class `Ui_MainWindow` (from `kilin_panel.ui`). This file defines the main window layout and all widgets (buttons, LEDs, group boxes, etc.).
  - Do not edit this file manually if you regenerate the UI from Qt Designer; changes will be overwritten.

- `src/module_panel.py`
  - Auto-generated PyQt5 UI code for the motor command widget (originally from `motor_cmd.ui`).
  - Defines `Ui_Form` which lays out input fields and state displays for hip/steering/hub motors.

- `src/module_widget.py`
  - A thin wrapper `ModulePanel` (Qt widget) that mixes in `Ui_Form` from `module_panel.py`.
  - Provides:
    - `get_leg_cmd()` — reads UI inputs (modes, PID gains, position/velocity/torque commands) and returns a dictionary used by `MotorNode` when building `MotorCmdStamped` messages.
    - `update_motor_state()` — used to display incoming motor state feedback (position/velocity/torque).

- `src/power_node.py`
  - A lightweight ROS2 node `PowerNode` (subclass of `rclpy.node.Node`) responsible for:
    - Publishing `kilin_msgs/PowerCmdStamped` on `/power/command`.
    - Subscribing to `/power/state` (`PowerStateStamped`) and posting voltage update events to the Qt GUI thread.
  - Contains a small custom Qt `VoltageUpdateEvent` used to safely pass voltage values into the GUI thread.

- `src/motor_node.py`
  - ROS2 node `MotorNode` that:
    - Publishes `kilin_msgs/MotorCmdStamped` on `/motor/command` based on the values collected from the four `ModulePanel` widgets.
    - Subscribes to `/motor/state` (`MotorStateStamped`) and posts `MotorStateUpdateEvent` to the GUI to update state displays for each motor.
  - Contains a Qt custom event class `MotorStateUpdateEvent` for thread-safe UI updates.

- `launch/kilin_panel.launch.py`
  - A ROS2 launch file that starts the packaged `kilin_panel` executable (console script). Use it with `ros2 launch`.

- `setup.py` and `package.xml`
  - Packaging metadata and installation configuration (defines console script entry point `kilin_panel`).

## GUI features overview

- Power controls:
  - Digital / Signal / Power toggles with LED indicators.
  - Emergency Stop button to immediately clear power states and publish a power-off command.
- Module controls (A..D):
  - Each module contains three motor sections — hip, steering, hub — with fields for mode, PID gains and command values.
  - `Send` button reads all four modules and publishes a single `/motor/command` message.
- Feedback:
  - Voltage display (updated from `/power/state`).
  - Motor position/velocity/torque displays for each motor (updated from `/motor/state`).

## Mode switching & forwarding behavior

- The GUI supports two control modes (ComboBox `comboBox_input`): `UI` and `Manual`.
  - UI mode: user edits module panels and presses `Send` to publish a manual `/motor/command`.
  - Manual mode: the GUI forwards incoming `/kilin/motor_cmd_raw` messages to `/motor/command` (useful when running the joystick+converter pipeline) and updates the module panels in read-only mode for monitoring.

## ROS nodes, executor and threading

- On startup the GUI initializes ROS2 (`rclpy.init`) and creates three nodes:
  - `PowerNode` — publishes `/power/command`, subscribes to `/power/state` and posts voltage updates to the GUI thread.
  - `MotorNode` — publishes `/motor/command` when the user sends manual commands and subscribes to `/motor/state` to receive motor feedback.
  - `kilin_panel_ui` — an internal node used to forward `/kilin/motor_cmd_raw` → `/motor/command` and to publish zero commands on mode switches.

- A `MultiThreadedExecutor` is used and spun in a background thread so ROS callbacks don't block the Qt event loop. UI updates coming from ROS callbacks are posted as Qt events or emitted as signals and handled in the main GUI thread.

## Cleanup and shutdown

- The panel implements a `cleanup()` routine called on window close or on SIGINT which shuts down the executor, destroys nodes and calls `rclpy.shutdown()`. The executor thread is joined with a short timeout to ensure a clean exit.
